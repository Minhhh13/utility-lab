# Map-only utility selection

The public website is [utilitylab.au](https://utilitylab.au), with local development available at http://127.0.0.1:5180.

Normal Lineups browsing gives the map the full working area. Desktop utility filters sit on the left, with the team switch and zoom controls on the right. Portrait phones place both controls below the map. Tablet rails use smaller icon controls. There is no reference sidebar, location list or permanent detail panel. A personal editor can still open explicitly from the viewer's actions.

The main map uses neutral 36px circles with actual Smoke, Flash, Molly and HE glyphs and 46px hit areas. Nearby places share a fixed group marker at a real member coordinate. Panning moves it with the map; it never slides into an offset grid. Main markers have no pastel pie sectors or leader lines. Hover/focus and accessible labels retain group context. Zoom can refine nearby groups.

The map asks only for necessary choices after active filters. A group with one available utility and one exact destination opens standing pins directly. One utility with several destinations opens landing pins directly. Several utilities open the radial; choosing a type shows landing pins only when several exact destinations exist, otherwise it opens standing pins. Selecting a singleton standing pin opens its Photos-first viewer in one click. Shared standing pins open a visual map chooser before the exact recipe. There is no named-area or landing-choice list.

Each landing point has a named button with the utility icon and a line to its registered dot. Hovering or focusing a button highlights its dot. Tapping either opens that landing’s throw-from choices. When several points share a name, small numbers distinguish them in top-to-bottom radar order. The buttons reserve 44px of touch height and make room for the map controls. Dense selections show up to six choices per page on narrow phones and ten on wider screens. Changing pages preserves the map camera.

While the radial is open, the entire overview-marker layer is hidden so utility choices have clear space. The old overlapping chooser hint is removed.

The selected utility exposes every distinct registered destination represented by the group. Its identity includes semantic area, map, floor, side, utility type and the publisher's two-decimal destination coordinate. A public scope containing an explicit spawn family instead shares one landing choice only for the same exact normalized target name and coverage qualifier; source impact variation does not add redundant choices. Other names, inside/outside/close/far qualifiers and personal records remain separate. All original points stay recorded. Full catalogue membership is retained behind the overview: the 1,283-record preference subset affects ordering, not availability among the **1,558 guides / 1,478 sources**. This avoids hiding Mid Doors, Lower Tunnels, Xbox or another nearby place inside the first few recipes.

Each landing has a labelled button connected to its actual dot. Repeated names receive stable numbers. The picker reserves space for the full button and divides dense groups into pages with up to six choices on phones or ten on desktop. Selecting a landing opens every matching throw-from recipe on its supported floor. When several standing positions share a marker, selecting it opens a radar detail. Verified numbered spawns appear at their coordinates when the buttons fit. Closely spaced alternatives use leader lines. Approximate areas use a dashed mark and the Position photo supplies the standing reference. The library includes all five Ancient Top Mid, Ancient Elbow and Mirage Window spawns. [Origin evidence](lineup-origins.md).

A saved personal guide without published origin proof stays reachable from its own target: a singleton opens its own viewer directly, and several personal guides use a visual **Your lineups** target action. Copying a publisher source URL does not confer its standing location. A personal action badge may be offset with a leader for tap clearance; this does not alter the saved target or published standing coordinates. Offscreen target actions are hidden while panning. Personal editing and exports remain available from the resulting viewer.

Group, utility, landing and standing selections, opening photos, and Back to targets preserve the current zoom and pan on the same floor. Selection does not zoom or recenter the map; keyboard focus also avoids scrolling. Manual wheel/pinch zoom remains available to 4×, with pan and Fit controls. A different map or floor retains its normal fit behavior. Back to targets also cancels a pending source lookup. Keyboard selection and reduced motion remain immediate.

Display settings groups In-game view, persistent Auto / 16:9 / 4:3 desktop frames and Hide top bar. A floating 44px Show top bar control restores the header. Narrow phones fit automatically while preserving the desktop frame preference. These controls preserve map geometry and editor state. Home stays full-screen; the saved ratio applies to the working tabs.

The viewer header contains the Save/Unsave star and ellipsis menu. Copy lineup link, Download lineup and Make my own remain available; personal guides also offer Edit personal lineup and Delete your lineup. Saving a personal edit returns to the viewer. Global Saved, combined utility filters, source attribution, uploaded-media backups and existing deep links remain intact.

Active implementation includes `Utilities.tsx`, `utility-markers.ts`, `UtilityTargetMarker.tsx`, `MarkerChoices.tsx`, `origin-options.ts`, `OriginChoices.tsx`, `GuideActions.tsx` and `useMapNavigation.ts`. `AreaChoices.tsx` and `LandingChoices.tsx` are legacy components, not the active flow. Executable contracts are maintained in the marker/navigation models and overview, landing, origin and viewer browser suites. Final run results belong in the [verification record](verification.md).

Public deployment uses a verified filtered static artifact; publishing it and pushing source to GitHub are separate actions. This document does not establish that the current working tree is deployed. Browser storage is separate at each origin: use Workspace settings → Export workspace locally, then Import backup on the public URL to transfer saved work. Bundled offline content uses explicit download actions. A separate browser-only cache reuses up to 12 successfully viewed publisher photos for seven days, and only the next slide is warmed after the current image loads. Browsing map pins does not prefetch galleries or videos, and no database/image proxy is added. See [image caching](image-caching.md).

The standing-position review uses publisher footage and recorded world coordinates. Its evidence and scope are documented in [throw-from map locations](lineup-origins.md).
