# Utility Lab

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

React, TypeScript and Vite with lazy workspace routes, static production assets and progressive web app support. Cloudflare Pages serves the public static release at https://utilitylab.au. A read-only Node server provides local delivery at http://127.0.0.1:5180 with compression and cache headers. A Capacitor iOS project wraps the shared web code, with Filesystem and Share integrations prepared in source. Native compilation and signing require macOS/Xcode and have not been performed.

## Users and Purpose

Counter-Strike 2 players preparing rounds on desktop or iPhone and looking up utility through the Steam in-game browser. The active product combines a tactic board, map-based photo/video lineups and local workspace statistics. Playbooks combines the board and lineup guides in timed five-player round plans. Frequent editing should respond immediately, and reference media should load only when requested.

## Operating and Delivery Constraints

The verified public website is hosted on Cloudflare Pages at [utilitylab.au](https://utilitylab.au), following the user’s authorization. Local development remains at http://127.0.0.1:5180. The complete application source is synchronized to the [public repository](https://github.com/Minhhh13/utility-lab). Production publishing uploads a verified filtered static artifact; Git pushes and website deployments are separate operations.

The runtime is the website and local server. It does not launch CS2, access its installation or game files, inject software or read live gameplay. Reference media comes from online sources; no game capture or gameplay automation is part of the product.

Metadata and saved records use localStorage; personal photo bytes use IndexedDB. Legacy inline-photo records remain readable. Original remote images stay on their HTTPS source servers, require internet and remain URL references in backups; they are not added to the offline pack. Browser origin determines the workspace: the public site, localhost, another hostname or port, browser and device each have a separate store. Transfer existing local work using Workspace settings → Export workspace on the old origin and Import backup on the new one. Files provide backup and transfer; there is no automatic sync or account service.

The production service worker supports cached app use on localhost/HTTPS. Plain HTTP LAN access can serve a phone while the local server is running, but does not provide the usual secure-context offline installation. Creator videos require internet access and load only after a request. Native exports are wired to a share sheet in source; hardware behavior remains to be verified.

## Evidence and Product Principles

Use real radar artwork, attributed creator links and user-uploaded aim photographs. Decorative pixel art belongs to the entry, never to lineup evidence. Map pins are approximate navigation aids, not measured grenade footprints or exact aim points. Source metadata and observed playback checks do not establish current-game throw accuracy or future media availability.

Keep frequent actions immediate, let the map lead, preserve recoverable editing, and explain local data plainly. Automated Edge and phone-sized WebKit evidence is recorded separately from physical iPhone, actual Steam overlay and native compilation in [verification](utility-lab/docs/verification.md).
